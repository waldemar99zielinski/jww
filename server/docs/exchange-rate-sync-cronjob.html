Backend Design Analysis

Daily exchange-rate sync via a cron job

A scheduled job inside cmd/server that runs at 00:01, pulls the previous day's rates for every directed pair of the currencies it holds from the Frankfurter API, and records them as currency_exchange_rates rows in a single batched insert — designed to fit the existing Clean Architecture, hexagonal ports, unit-of-work and testing conventions of the jww server.

Target: server/ Provider: Frankfurter v2 (no API key) Scheduler: robfig/cron v3 Default: 00:01 UTC, previous day Write path: one bulk INSERT

01 Recommendation (TL;DR)

Use github.com/robfig/cron/v3, a new outbound port RateSource, and a batched write path. Wrap the cron library in one infrastructure package (internal/infrastructure/scheduler), implement the port in a new adapter (internal/adapter/frankfurter), and put the orchestration in a new method on the existing workflow (CurrencyExchangeRateWorkflow.SyncDaily). Persist the whole day's rates with a single multi-row upsert (INSERT … ON CONFLICT … DO UPDATE) — no schema migration is required.
  • Library: robfig/cron/v3 — the de-facto Go cron library, zero transitive dependencies, standard cron syntax, per-schedule timezone, built-in panic recovery & overlapping-run guards, and a Stop() that returns a context so it slots straight into the server's existing SIGTERM shutdown.
  • Coverage: fetch and store the full directed matrix among all present currencies — N×(N−1) pairs (EUR→USD and USD→EUR, EUR→PLN and PLN→EUR, …). The job is base-agnostic: the base flag is irrelevant here, because the base can change and every pair is fetched anyway.
  • No Quote DTO: a new, code-only domain.CurrencyExchangeRateFlatten (FromCurrencyCode / ToCurrencyCode / Rate / RecordedAt) is what the port, the service and the adapter share. The existing nested domain.CurrencyExchangeRate is left untouched for the read/HTTP paths.
  • By date: the schedule fires at 00:01 and fetches the previous calendar day's rates via Frankfurter's ?date=. The RateSource port takes an explicit asOf date, so the same primitive also serves ad-hoc backfill of any day.
  • Batching & upsert: the whole matrix is written in one statement inside one unit of work — a bulk upsert (ON CONFLICT … DO UPDATE), not one statement per pair and not a silent skip.
  • Re-runnable (replace, not skip): each row's recorded_at is the rate's own business date at 00:00 UTC, and conflicts on (from, to, recorded_at) are resolved with DO UPDATE SET rate = EXCLUDED.rate. Re-running, restarting, or catching up the same day replaces that day's rates — never duplicates and never silently no-ops.
  • Never fail silently: a pair the provider can't return, an unconfigured code, or an empty day is returned as a structured warning and logged at WARN at the boundary; hard failures log at ERROR. Nothing is dropped without a log line.
  • Layering: the cron library is confined to the outermost layer; the workflow depends on the RateSource port, never on the Frankfurter adapter. Skipped items are returned, then logged once at cmd/server — services and adapters still don't log (see §07).
  • Loop of control: HTTP fetch happens before the DB transaction opens (no tx held during network I/O), and all rows land in one transaction.

  • Deployed everywhere (5.5k+ importers); its API is stable and well understood.
  • cron.Stop() returns a context.Context that closes when running jobs finish — a natural fit for main.go's 10s graceful shutdown.

Note on release cadence

robfig/cron v3.0.1 dates to 2020, but the package is feature-complete and its issue tracker is quiet rather than abandoned. If a policy requires an actively released dependency, netresearch/go-cron is a near drop-in fork with the same API. Either way, the wrapper below keeps the choice swappable in one file.

03 The Frankfurter API

Frankfurter is a free, open-source exchange-rate API aggregating 104 central banks and official sources. No API key, no quotas. Its FAQ explicitly encourages storing daily observations locally for caching — which is precisely what this job does.

Endpoints used

# One base at a time, every other held currency as quotes → one request per currency.
curl "https://api.frankfurter.dev/v2/rates?base=EUR&quotes=PLN,USD"
// => [{"date":"2026-10-15","base":"EUR","quote":"PLN","rate":4.3711},
//     {"date":"2026-10-15","base":"EUR","quote":"USD","rate":1.0834}, ...]

# Add &date=YYYY-MM-DD to fetch a specific day — this is what the sync uses.
curl "https://api.frankfurter.dev/v2/rates?base=EUR&quotes=PLN,USD&date=2026-10-14"
// => [{"date":"2026-10-14","base":"EUR","quote":"PLN","rate":4.3757},
//     {"date":"2026-10-14","base":"EUR","quote":"USD","rate":1.1198}]

# Unknown / not-yet-published dates return an EMPTY array, not an error.
curl "https://api.frankfurter.dev/v2/rates?base=EUR&quotes=PLN&date=2030-01-01"
// => []

# A single pair, if you ever need exactly one (same data, same date param).
curl "https://api.frankfurter.dev/v2/rate/eur/pln?date=2026-10-14"
// => {"date":"2026-10-14","base":"EUR","quote":"PLN","rate":4.3757}
PropertyValue / implication
Base URLhttps://api.frankfurter.dev (configurable, so it can be self-hosted or pointed at a test double)
AuthNone. Anonymous, no request logging — nothing secret to configure.
rateUnits of quote per 1 unit of base. Returned as a bare JSON number (e.g. 4.3711). Decode it as json.Number and hand the text to domain.ParseExchangeRate — never float64.
date (query)Optional ?date=YYYY-MM-DD selects a specific day. The sync passes it explicitly (the previous calendar day) so a run is deterministic regardless of when the tick fires.
date (response)The rate's business date, echoed back — for a valid request it equals the date asked for. This is what we anchor recorded_at to.
Unknown datesA date with no data (future, or before the series starts) returns an empty array, not an error — surfaced as a warning and logged, never a silent success.
ErrorsA quote the provider has no rate for is simply absent from the array — the adapter records it as a skipped pair (warning). A whole-request 5xx, 404/422, or a decode failure is a hard error that aborts the run.
CadenceDaily; ECB-sourced rates publish around 16:00 CET, so by 00:01 the previous day is fully published. No intraday movement to chase.
We store the full matrix — both directions of every pair. The requirement is a daily rate for all present currencies, so the job records every ordered pair among them. For {PLN, EUR, USD} that is six rows: PLN→EUR, PLN→USD, EUR→PLN, EUR→USD, USD→PLN, USD→EUR. Nothing downstream is consulted to decide the direction: the base flag can change over time, so the sync deliberately fetches both directions of every pair and never treats any currency as the target.
Shape of the fetch: one request per base, no inversion. Frankfurter returns base→quote for a single base per request, so the adapter makes N requests — one per present currency as base, the rest as quotes — and collects all N×(N−1) directed pairs straight from the provider. Every stored rate is a direct observation; no row is derived by computing 1/rate, which would lose precision in the fixed-point ExchangeRate type. The app holds a handful of currencies and the API is edge-cached with no quota, so N calls once a day is negligible. The RateSource port keeps this shape swappable, and every request also carries &date=…, pinning all N calls to the same target day. Any quote the provider omits is returned as a skipped pair (with a reason), so the workflow can log it — the adapter never drops a pair silently.

06 Runtime flow diagram

  1. The cron tick fires; the scheduler wrapper builds a fresh domain.AppContext with source_type=scheduler, a new flow_id, and a per-run timeout, then calls the job.
  2. SyncDaily lists every currency the app currently holds. It does not consult the base flag — the base can change, and every pair is fetched regardless. Fewer than two currencies short-circuits (nothing to pair).
  3. It computes the previous calendar day and calls rateSource.Rates(ctx, codes, asOf). The adapter issues one /v2/rates?base={code}&quotes=…&date=… request per currency and returns the readable pairs as domain.CurrencyExchangeRateFlatten values plus a RateSkip for every pair the provider had no rate for. Transport/decoding/5xx errors abort the run; nothing is dropped without being reported.
  4. Only now does the workflow open one unit of work.
  5. It keeps only pairs whose codes are currencies the app actually holds (FK guard) and hands the whole batch straight to Service.UpsertMany, which validates and issues a single multi-row upsert — one round-trip, not one per pair. Pairs the provider couldn't return, and codes the app doesn't hold, are collected as warnings rather than dropped.
  6. Finish() commits once. Any error during validation or the upsert triggers Restore() and aborts.
  7. Back at the boundary, every collected warning is logged at WARN, the run summary (currencies / fetched / inserted / updated) at INFO, and a hard failure at ERROR.

07 Data, batching & upsert

Anchoring recorded_at to the rate's business date

Today Service.Create stamps RecordedAt = time.Now().UTC(). The table is an append-only log whose primary key is (from_currency_code, to_currency_code, recorded_at), and its own comment describes a row as “…was worth rate … as of recorded_at”. For a scheduled feed, the observation date is the meaningful instant, not the fetch time: the run pins the request to the previous calendar day and stores every row at that day, so a 00:01 tick on the 15th writes rows dated the 14th. 

-- store the API's business date at midnight UTC
recorded_at = time.Date(date.Year(), date.Month(), date.Day(), 0, 0, 0, 0, time.UTC)

Why this is better

  • Re-runnable upsert: a second run for the same business day collides on the primary key and replaces the rate — still exactly one row per pair per day.
  • Correct history: the row reads “rate as of 2026-10-15”, not “fetched at 16:02”.
  • Safe restarts / catch-up: re-running can never duplicate or drift.
  • Stable lookups: “latest rate for a pair at or before an instant” is unchanged.

No migration needed

The existing primary key currency_exchange_rates_pk is exactly the conflict target ON CONFLICT (from_currency_code, to_currency_code, recorded_at) needs for the DO UPDATE. The rate stays numeric(18,4), the distinct-currencies and positive-rate checks are unchanged, and the HTTP “create rate by hand” endpoint keeps using time.Now() because it is a separate code path.

What lands each run

For {PLN, EUR, USD} a single daily run writes six directed rows, all anchored to the same business date:

from_currency_codeto_currency_coderate
PLNEUR0.2288
PLNUSD0.2562
EURPLN4.3711
EURUSD1.0834
USDPLN3.9030
USDEUR0.9230

Illustrative values — each one is a direct Frankfurter observation, never a reciprocal computed locally. Each row is carried by CurrencyExchangeRateFlatten (FromCurrencyCode/ToCurrencyCode), so it maps field-for-field with no joined currency objects.

One batched upsert (replace on conflict)

The whole matrix is written in a single statement that replaces any existing row for the same pair and day; Squirrel builds it by calling .Values(...) once per row:

INSERT INTO currency_exchange_rates (from_currency_code, to_currency_code, rate, recorded_at)
VALUES ($1, $2, $3, $4),
       ($5, $6, $7, $8),
       ...
       ($n-3, $n-2, $n-1, $n)
ON CONFLICT (from_currency_code, to_currency_code, recorded_at)
DO UPDATE SET rate = EXCLUDED.rate
RETURNING (xmax = 0) AS inserted;
  • One round-trip for the entire day's matrix instead of N×(N−1) separate statements.
  • Replace, never skip: a re-run updates that day's rows in place (DO UPDATE), so it can never silently no-op or duplicate.
  • Count what changed: RETURNING (xmax = 0) distinguishes inserts (xmax = 0) from updates — that is SyncResult.Inserted vs SyncResult.Updated, both logged.
  • No intra-batch conflicts: every row shares the same business-date recorded_at and each directed pair is unique, so the same key never appears twice in one statement. (A duplicate key within one DO UPDATE statement would be a fatal error — loudly, never silently.)

No silent failures

Every path that does not produce a stored rate is surfaced and logged at the boundary — nothing is swallowed:

  • Provider has no rate for a pair → returned as a RateSkip{From, To, Reason}; logged at WARN.
  • Empty result for the day (holiday/future date) → logged at WARN (“no rates returned for …”).
  • A returned code isn't a configured currency → dropped from the batch but logged at WARN.
  • Transport / decode / 5xx → the run aborts with an error; logged at ERROR.
  • Validation failure (a bad row) → aborts before I/O; logged at ERROR.

Services and adapters don't log (repo convention): they return warnings/errors, and cmd/server logs them once — see §09.7.

Precision

ExchangeRate is fixed-point 1e-4 (numeric(18,4)). Frankfurter returns up to five significant decimals (e.g. 0.94082), which domain.ParseExchangeRate rounds to four — fine for the currencies this app holds. Because every row is stored directly from the provider (no inversion), the only residual concern is a pair whose true rate is below ~0.00005, which would round toward zero and trip the “rate must be positive” check. Flagged as a risk; the seeded set (EUR, USD, PLN) is unaffected.

Never decode the rate as float64. Use json.Number for the rate field and pass its text to domain.ParseExchangeRate. This preserves the repo-wide “no floats for money/rates” rule and keeps the exact decimal the API returned.

Sketches are illustrative — signatures, error handling and imports follow the repo's existing conventions.

9.1 Modify internal/domain/{currency_exchange_rate,app_context}.go

Add CurrencyExchangeRateFlatten (new)

A second, code-only struct for the sync path. It coexists with the existing CurrencyExchangeRate, which keeps its nested Currency values for the read/HTTP paths — the existing entity is not changed. The flatten type is exactly what a provider can supply and what the append-only table stores: two codes, a rate, an instant. 

// CurrencyExchangeRateFlatten is the code-only projection used by the sync:
// the shape an external provider supplies and the shape the table stores.
// CurrencyExchangeRate (nested) remains the read/HTTP shape.
type CurrencyExchangeRateFlatten struct {
    FromCurrencyCode string
    ToCurrencyCode   string
    Rate             ExchangeRate
    RecordedAt       time.Time
}

func (r CurrencyExchangeRateFlatten) Validate() error {
    if r.FromCurrencyCode == r.ToCurrencyCode {
        return fmt.Errorf("from_currency_code and to_currency_code must differ")
    }
    if r.Rate <= 0 {
        return fmt.Errorf("rate must be positive")
    }
    return nil
}

Mirrors the same two business-rule CHECKs on currency_exchange_rates (distinct currencies, positive rate) that CurrencyExchangeRate.Validate() enforces.

Add a scheduler request source

Give non-HTTP entry points a first-class source so the logger stays coherent.

const (
    RequestSourceTypeHTTP      RequestSourceType = "http"
    RequestSourceTypeScheduler RequestSourceType = "scheduler" // new

// Optional: name the job so logs carry it.

    Type      RequestSourceType

9.2 Modify internal/service/currency_exchange_rate/currency_exchange_rate.go

Declare the outbound port and the batched upsert write path. No Quote, no service-local DTO — the port, the service and the repo all speak domain.CurrencyExchangeRateFlatten. Skips are returned, never swallowed; this package still does not log.

// RateSkip is a pair the source could not produce a rate for, with the reason,
// so the boundary can log it instead of dropping it silently.
type RateSkip struct{ From, To, Reason string }

// RateFetch is what a source returns for one day: the pairs it read and the
// pairs it skipped.
type RateFetch struct {
    Rates   []domain.CurrencyExchangeRateFlatten
    Skipped []RateSkip
}

// RateSource is the outbound port for fetching rates among a set of currencies.
// It returns every directed pair (N×(N−1) rows) for the given day; a zero asOf
// means the provider's latest. Implemented in internal/adapter/frankfurter.
type RateSource interface {
    Rates(ctx domain.AppContext, currencies []string, asOf time.Time) (RateFetch, error)
}

// UpsertCounts reports how a batch changed the table.
type UpsertCounts struct{ Inserted, Updated int }

type Repository interface {
    Create(ctx domain.AppContext, exchangeRate domain.CurrencyExchangeRate, uow ...unit_of_work.UnitOfWork) error
    // UpsertMany writes a whole batch in one statement, replacing rate on a
    // (from,to,recorded_at) conflict. Returns inserted/updated counts.
    UpsertMany(ctx domain.AppContext, rates []domain.CurrencyExchangeRateFlatten, uow ...unit_of_work.UnitOfWork) (UpsertCounts, error)
    GetByCurrencies(ctx domain.AppContext, from, to domain.Currency, asOf time.Time, uow ...unit_of_work.UnitOfWork) (*domain.CurrencyExchangeRate, error)
    List(ctx domain.AppContext, uow ...unit_of_work.UnitOfWork) ([]domain.CurrencyExchangeRate, error)
}

// UpsertMany stamps every row with a UTC RecordedAt, validates the batch, then
// upserts it in ONE statement (replace on conflict). Returns inserted/updated
// counts; the first invalid row aborts before any I/O.
func (s *Service) UpsertMany(ctx domain.AppContext, rates []domain.CurrencyExchangeRateFlatten, uow ...unit_of_work.UnitOfWork) (UpsertCounts, error) {
    if len(rates) == 0 { return UpsertCounts{}, nil }
    normalized := make([]domain.CurrencyExchangeRateFlatten, 0, len(rates))
    for _, r := range rates {
        r.RecordedAt = r.RecordedAt.UTC()
        if err := r.Validate(); err != nil {
            return UpsertCounts{}, err
        }
        normalized = append(normalized, r)
    }
    return s.repository.UpsertMany(ctx, normalized, uow...)
}

Create is left untouched so the manual HTTP endpoint keeps its “now” timestamp and single-row semantics.

9.3 Modify internal/adapter/gateway/postgres_currency_exchange_rate_repository.go

func (r *PostgresCurrencyExchangeRateRepository) UpsertMany(ctx domain.AppContext, rates []domain.CurrencyExchangeRateFlatten, uow ...unit_of_work.UnitOfWork) (currency_exchange_rate.UpsertCounts, error) {
    if len(rates) == 0 { return currency_exchange_rate.UpsertCounts{}, nil }
    db, err := dbFromUnitOfWork(r.db, uow...)
    if err != nil { return currency_exchange_rate.UpsertCounts{}, err }

    insert := psql.Insert("currency_exchange_rates").
        Columns("from_currency_code", "to_currency_code", "rate", "recorded_at")
    for _, rate := range rates {
        rateNumeric, err := exchangeRateToNumeric(rate.Rate)
        if err != nil { return currency_exchange_rate.UpsertCounts{}, err }
        insert = insert.Values(rate.FromCurrencyCode, rate.ToCurrencyCode, rateNumeric, rate.RecordedAt)
    }
    sql, args, err := insert.
        Suffix("ON CONFLICT (from_currency_code, to_currency_code, recorded_at) DO UPDATE SET rate = EXCLUDED.rate RETURNING (xmax = 0)").
        ToSql()
    if err != nil { return currency_exchange_rate.UpsertCounts{}, err }

    rows, err := db.Query(ctx.Context(), sql, args...)
    if err != nil { return currency_exchange_rate.UpsertCounts{}, err }
    defer rows.Close()

    var counts currency_exchange_rate.UpsertCounts
    for rows.Next() {
        var inserted bool
        if err := rows.Scan(&inserted); err != nil { return counts, err }
        if inserted { counts.Inserted++ } else { counts.Updated++ }
    }
    if err := rows.Err(); err != nil { return counts, err }
    return counts, nil
}

Squirrel accumulates one VALUES group per .Values(...) call, producing a single multi-row statement capped by pgx's parameter limit (~65,535 → ~16k rows; the matrix is far smaller). ON CONFLICT … DO UPDATE returns one row per affected row; xmax = 0 marks a fresh insert (Postgres stamps xmax on updated tuples).

9.4 New internal/adapter/frankfurter/frankfurter.go

// Package frankfurter implements currency_exchange_rate.RateSource using the
// Frankfurter API. It is the only place that speaks HTTP to an external provider.
package frankfurter

type Config struct {
    BaseURL        string `env:"FRANKFURTER_BASE_URL" bind:"optional" default:"https://api.frankfurter.dev"`
    TimeoutSeconds int64  `env:"FRANKFURTER_TIMEOUT_SECONDS" bind:"optional" default:"15"`
}

func LoadConfig() (Config, error) { return configuration.Load[Config]() }

type Client struct {
    baseURL string
    http    *http.Client
}

func NewClient(cfg Config) *Client {
    return &Client{
        baseURL: strings.TrimRight(cfg.BaseURL, "/"),
        http:    &http.Client{Timeout: time.Duration(cfg.TimeoutSeconds) * time.Second},
    }
}

type rateResponse struct {
    Date  string      `json:"date"`
    Base  string      `json:"base"`
    QuoteCode string  `json:"quote"`
    Rate  json.Number `json:"rate"` // never float64
}

// Rates fetches base→quote for every currency as base for asOf (zero = latest),
// returning the readable pairs and a RateSkip for every pair the provider omitted.
func (c *Client) Rates(ctx domain.AppContext, currencies []string, asOf time.Time) (currency_exchange_rate.RateFetch, error) {
    out := currency_exchange_rate.RateFetch{
        Rates: make([]domain.CurrencyExchangeRateFlatten, 0, len(currencies)*(len(currencies)-1)),
    }
    for _, base := range currencies {
        quotes := make([]string, 0, len(currencies)-1)
        for _, code := range currencies {
            if code != base { quotes = append(quotes, code) }
        }
        batch, err := c.rates(ctx, base, quotes, asOf)
        if err != nil { return currency_exchange_rate.RateFetch{}, err }
        out.Rates = append(out.Rates, batch.Rates...)
        out.Skipped = append(out.Skipped, batch.Skipped...)
    }
    return out, nil
}

// rates GETs /v2/rates?base=…&quotes=…&date=… , maps each row to a flatten, and
// records a RateSkip for every requested quote the provider left out.
func (c *Client) rates(ctx domain.AppContext, base string, quotes []string, asOf time.Time) (currency_exchange_rate.RateFetch, error) {
    url := fmt.Sprintf("%s/v2/rates?base=%s&quotes=%s", c.baseURL, base, strings.Join(quotes, ","))
    if !asOf.IsZero() {
        url += "&date=" + asOf.Format("2006-01-02")
    }
    req, err := http.NewRequestWithContext(ctx.Context(), http.MethodGet, url, nil)
    // ... Do, then:
    //   !200 → wrapped error   (a hard failure that aborts the whole run)
    var body []rateResponse
    // json.NewDecoder(io.LimitReader(resp.Body, 1<<20)).Decode(&body)
    fetch := currency_exchange_rate.RateFetch{Rates: make([]domain.CurrencyExchangeRateFlatten, 0, len(body))}
    seen := make(map[string]struct{}, len(body))
    for _, row := range body {
        rate, err := domain.ParseExchangeRate(row.Rate.String())
        if err != nil { return currency_exchange_rate.RateFetch{}, err }
        date, err := time.Parse("2006-01-02", row.Date)
        if err != nil { return currency_exchange_rate.RateFetch{}, err }
        fetch.Rates = append(fetch.Rates, domain.CurrencyExchangeRateFlatten{
            FromCurrencyCode: row.Base, ToCurrencyCode: row.QuoteCode, Rate: rate, RecordedAt: date,
        })
        seen[row.QuoteCode] = struct{}{}
    }
    for _, q := range quotes {
        if _, ok := seen[q]; !ok {
            fetch.Skipped = append(fetch.Skipped, currency_exchange_rate.RateSkip{
                From: base, To: q, Reason: "provider returned no rate",
            })
        }
    }
    return fetch, nil
}

9.5 Modify internal/service/workflow/currency_exchange_rate_workflow.go

type CurrencyExchangeRateWorkflow struct {
    currencyService     *currency.Service
    exchangeRateService *currency_exchange_rate.Service
    rateSource          currency_exchange_rate.RateSource // new: the port, not the adapter
    uowManager          unit_of_work.Manager
}

type SyncResult struct {
    Currencies int
    Fetched    int
    Inserted   int
    Updated    int
    Skipped    int
    Warnings   []string // every skip/drop, for the boundary to log at WARN
}

// SyncDaily records the previous calendar day's rate for every directed pair of the
// currencies the app holds (N×(N−1) rows) in one batched upsert. It runs at 00:01,
// when the previous day is fully published.
func (w *CurrencyExchangeRateWorkflow) SyncDaily(ctx domain.AppContext) (SyncResult, error) {
    return w.Sync(ctx, time.Now().UTC().AddDate(0, 0, -1))
}

// Sync records a specific day's rates. It is base-agnostic (the base flag is never
// consulted) and never drops a pair silently: every skip or unconfigured code is
// appended to Warnings so the boundary can log it. A zero asOf asks for the latest day.
func (w *CurrencyExchangeRateWorkflow) Sync(ctx domain.AppContext, asOf time.Time) (SyncResult, error) {
    currencies, err := w.currencyService.List(ctx)
    if err != nil { return SyncResult{}, err }

    result := SyncResult{Currencies: len(currencies)}
    if len(currencies) < 2 { return result, nil } // nothing to pair

    codes := make([]string, 0, len(currencies))
    for _, c := range currencies { codes = append(codes, c.Code) }
    known := make(map[string]struct{}, len(codes))
    for _, code := range codes { known[code] = struct{}{} }

    fetch, err := w.rateSource.Rates(ctx, codes, asOf) // network first…
    if err != nil { return SyncResult{}, err }
    result.Fetched = len(fetch.Rates)
    result.Skipped = len(fetch.Skipped)

    // surface every skip instead of swallowing it
    for _, s := range fetch.Skipped {
        result.Warnings = append(result.Warnings, fmt.Sprintf("no rate for %s→%s on %s: %s",
            s.From, s.To, asOf.Format("2006-01-02"), s.Reason))
    }
    if len(fetch.Rates) == 0 {
        result.Warnings = append(result.Warnings,
            fmt.Sprintf("provider returned no rates for %s", asOf.Format("2006-01-02")))
    }

    // keep only pairs whose codes are currencies we actually hold (FK guard)
    rates := make([]domain.CurrencyExchangeRateFlatten, 0, len(fetch.Rates))
    for _, q := range fetch.Rates {
        _, okF := known[q.FromCurrencyCode]
        _, okT := known[q.ToCurrencyCode]
        if !okF || !okT {
            result.Warnings = append(result.Warnings,
                fmt.Sprintf("dropped rate %s→%s: currency not configured", q.FromCurrencyCode, q.ToCurrencyCode))
            continue
        }
        rates = append(rates, q)
    }

    active, err := w.uowManager.Create(ctx) // …then one transaction
    if err != nil { return SyncResult{}, err }
    counts, err := w.exchangeRateService.UpsertMany(ctx, rates, active) // ONE upsert
    if err != nil { _ = active.Restore(ctx); return SyncResult{}, err }
    if err := active.Finish(ctx); err != nil { return SyncResult{}, err }

    result.Inserted = counts.Inserted
    result.Updated = counts.Updated
    return result, nil
}

9.6 New internal/infrastructure/scheduler/scheduler.go

// Package scheduler runs jobs on a cron schedule. It is the only package that
// imports the cron library; everything else sees just the Job callback.
package scheduler

var log = logger.New().WithComponent("scheduler")

type Job func(ctx domain.AppContext) error

type Config struct {
    Enabled        bool   `env:"EXCHANGE_RATE_SYNC_ENABLED" bind:"optional" default:"false"`
    Spec           string `env:"EXCHANGE_RATE_SYNC_CRON" bind:"optional" default:"1 0 * * *"`
    Timezone       string `env:"EXCHANGE_RATE_SYNC_TZ" bind:"optional" default:"UTC"`
    TimeoutSeconds int64  `env:"EXCHANGE_RATE_SYNC_TIMEOUT_SECONDS" bind:"optional" default:"60"`
    RunOnStart     bool   `env:"EXCHANGE_RATE_SYNC_RUN_ON_START" bind:"optional" default:"false"`
}

func LoadConfig() (Config, error) { return configuration.Load[Config]() }

type Scheduler struct {
    cron    *cron.Cron
    job     Job
    timeout time.Duration
}

func New(cfg Config, job Job) (*Scheduler, error) {
    loc, err := time.LoadLocation(cfg.Timezone)
    if err != nil { return nil, fmt.Errorf("scheduler: invalid timezone %q: %w", cfg.Timezone, err) }
    s := &Scheduler{job: job, timeout: time.Duration(cfg.TimeoutSeconds) * time.Second}
    s.cron = cron.New(
        cron.WithLocation(loc),
        cron.WithLogger(cronLogger{}),
        cron.WithChain(cron.Recover(cronLogger{}), cron.SkipIfStillRunning(cronLogger{})),
    )
    if _, err := s.cron.AddFunc(cfg.Spec, s.run); err != nil {
        return nil, fmt.Errorf("scheduler: invalid spec %q: %w", cfg.Spec, err)
    }
    return s, nil
}

func (s *Scheduler) Start() { s.cron.Start() }

// Stop waits for any in-flight run, bounded by ctx (main.go's shutdown budget).
func (s *Scheduler) Stop(ctx context.Context) error {
    select {
    case <-s.cron.Stop().Done(): return nil
    case <-ctx.Done(): return ctx.Err()
    }
}

func (s *Scheduler) run() {
    ctx, cancel := context.WithTimeout(context.Background(), s.timeout)
    defer cancel()
    var appCtx domain.AppContext
    appCtx.SetContext(ctx)
    appCtx.SetRequestSource(domain.RequestSource{Type: domain.RequestSourceTypeScheduler})
    appCtx.SetFlowID(uuid.NewString())

    started := time.Now()
    if err := s.job(appCtx); err != nil {
        log.WithContext(appCtx).Error("scheduled job failed",
            slog.String("error", err.Error()), slog.Duration("duration", time.Since(started)))
        return
    }
    log.WithContext(appCtx).Info("scheduled job completed", slog.Duration("duration", time.Since(started)))
}

// cronLogger adapts the shared slog logger to cron's Logger interface.
type cronLogger struct{}
func (cronLogger) Info(msg string, kv ...any)           { log.Slog().Info(msg, kv...) }
func (cronLogger) Error(err error, msg string, kv ...any) { log.Slog().Error(msg, append(kv, slog.String("error", err.Error()))...) }

11 Operations & failure modes

Lifecycle & shutdown

  • Scheduler starts after migrations, alongside the HTTP listener.
  • On SIGTERM, sched.Stop(shutdownCtx) shares the existing 10s budget with srv.Shutdown, waiting for any in-flight run.
  • SkipIfStillRunning guarantees a slow run never overlaps the next tick.
  • Recover turns a panic into a logged error instead of a crashed process.

Observability

  • Per-run structured lines tagged with flow_id and source_type=scheduler: scheduler logs start/complete, cmd/server logs the per-run detail.
  • WARN for every skip/drop (missing pair, empty day, unconfigured code).
  • INFO summary carries currencies/fetched/inserted/updated/skipped and duration.
  • ERROR on failure (error + duration); retried at the next tick.

Failure modes

  • Provider down / 5xx / timeout: run aborts, transaction never opens, error logged at ERROR; next tick retries.
  • Unknown currency: reported as a RateSkip and logged at WARN — never silently omitted; the rest of the batch still lands.
  • Re-run / duplicate: upserts — that day's rates are replaced (reported as Updated, logged), never a silent no-op.
  • Bad row mid-batch: validation fails before I/O, nothing is written, logged at ERROR.

Volume & multiple replicas

  • N×(N−1) rows per run — 6/day for 3 currencies, 90/day for 10 — written in one statement.
  • If scaled out, each replica runs the job — but the upsert replaces on conflict, so the outcome is still one row per pair/day (wasted HTTP, no corruption).
  • For strict single-runner semantics later, swap in a leader-electing scheduler — only the scheduler package changes.

12 Risks & open questions

ItemImpactMitigation / decision needed
Two rate types coexist CurrencyExchangeRate (nested) and CurrencyExchangeRateFlatten (codes) can drift over time. Deliberate split: flatten is the write/port shape; the nested entity is the read/HTTP shape. Both Validate() the same two CHECK constraints, and each doc comment points at the other. The existing entity is not modified, so no consumer breaks.
xmax insert/update split RETURNING (xmax = 0) relies on a Postgres tuple-system column. Widely used and stable, but if it ever feels too clever, count RowsAffected() only (inserts + updates) and drop the split — the upsert itself is unaffected.
Matrix growth with many currencies N HTTP requests and N×(N−1) rows per day (one batch). Trivial at current scale (3 → 3 requests, 6 rows). The single-statement insert stays well under pgx's parameter limit (N×(N−1) × 4 params) for any realistic currency set.
Fixed-point precision for extreme pairs ExchangeRate is 1e-4; a direct rate below ~0.00005 rounds to zero and fails validation. Immune for PLN/EUR/USD. Every row is a direct observation (no inversion), so the fix is simply to widen the rate scale or skip such a pair. Recommend deferring until such a currency is actually added.
Catch-up for missed days A server that was offline skips that day's rate. Idempotent design makes EXCHANGE_RATE_SYNC_RUN_ON_START safe (it re-syncs yesterday). Backfill of arbitrary days is already possible: Sync(ctx, d) forwards any date to the date-capable RateSource; a future CLI can loop over a range.
Which currencies to sync Provider may not support a code the app holds. Always derive the set — and therefore the whole pair matrix — from the currencies table; codes the provider omits are simply not recorded.
Default enabled/disabled A background feature that suddenly makes outbound calls. Default EXCHANGE_RATE_SYNC_ENABLED=false; turn on per environment.
Library maintenance cadence robfig/cron's last release predates this project. Confined to one file; documented fallback to netresearch/go-cron if policy demands it.
Workflow constructor signature change Touches buildDeps and BuildTestDeps. Small, mechanical; called out in the checklist.
